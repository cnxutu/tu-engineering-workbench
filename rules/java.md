# Java 与 Spring Boot 规则

## 设计与编码

- 保持类和方法职责单一；通过清晰的接口和依赖注入管理协作关系。
- 控制器只处理协议适配和参数校验，业务规则放在应用/领域服务中，持久化细节留在仓储层。
- 使用具有业务含义的名称；避免无含义缩写、魔法数字和跨层传递实体对象。
- 新增依赖前说明必要性，并优先采用项目已有组件。

## 异常与返回

- 使用可区分、可定位的业务异常表达预期失败；技术异常保留根因并统一转换。
- 不捕获后静默忽略异常；日志不能替代错误处理。
- 对外 API 不泄露堆栈、凭据、内部 SQL 或实现细节。

## 日志与安全

- 日志应包含排查所需的业务标识和上下文，避免记录密码、令牌和完整个人敏感信息。
- 关键状态变更、外部调用失败和异常链路使用适当级别记录。
- 输入在边界层校验，授权在执行业务操作前完成。

## 测试

- 为新增或修复的业务规则提供可重复的自动化验证。
- 单元测试覆盖正常路径和关键失败路径；集成测试验证跨层契约。
