# 数据库规则

## 表设计

- 表和字段名称表达稳定业务语义，并遵循项目统一命名规则。
- 为关键业务约束建立数据库级约束；时间、状态和审计字段的语义必须明确。
- 避免把多值、结构化实体或无边界 JSON 当作关系模型的替代品；确有必要时说明查询和演进方式。

## 索引与查询

- 根据真实查询条件、排序和连接路径设计索引，并验证执行计划或压测结果。
- 避免冗余索引、低选择性单列索引和不受控的全表扫描。
- 分页查询使用稳定排序；批处理限制批次大小与事务范围。

## 数据迁移

- 迁移脚本必须可追踪、可重复执行或明确一次性执行条件。
- 线上结构变更采用“先兼容、再回填、后切换、最后清理”的方式。
- 执行前说明备份、耗时、锁表风险、校验与回滚路径。
