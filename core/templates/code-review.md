# 代码评审任务

> **简写任务类型：`C`** — Code Review（代码评审）。
>
> 填写时可直接使用 `C` 与 `g/b/s/c/r/i/p/v` 简写；本页是防遗漏的完整参考。字段约定见 [Prompt Compact Syntax](../prompt-compact-syntax.md)。

## 使用示例

```text
范围：P0 + P1
C
g: 评审设备状态缓存改动
b: 改动涉及 OSD 分包合并
s: 已完成 P1 实现与单元测试
c: 重点检查缓存完整性、兼容性和并发风险
r: 输出按严重程度排序的可行动问题；无问题时明确说明风险覆盖范围
i: P1
p: 先读取变更与相关缓存设计；只报告可复现或有明确证据的问题
v: 检查测试覆盖、关键分包场景和现有接口回归风险
```

## g — 目标（Goal）

<!-- 希望评审确认的质量目标或风险。 -->

## b — 背景（Background）

<!-- 需求链接、变更原因、相关设计和已有约定。 -->

## s — 当前状态（State）

<!-- 分支/提交范围、主要变更、已执行测试和已知问题。 -->

## c — 约束（Constraints）

<!-- 兼容性、安全、性能、发布窗口及明确不在本次范围内的事项。 -->

## r — 期望结果（Result）

<!-- 希望获得的评审结论、重点关注路径和输出格式。 -->

## i — 影响范围（Impact）

<!-- 受影响模块、接口、数据、用户、依赖和回归区域。 -->

## p — 实施要求（Plan）

<!-- 评审阅读顺序、重点风险、输出格式、证据要求和不在评审范围内的事项。 -->

## v — 验证方式（Verification）

<!-- 需检查的测试、场景、静态检查、日志或监控指标。 -->
