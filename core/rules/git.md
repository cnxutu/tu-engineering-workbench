# Git 规则

## 分支

- 一个分支只承载一个可审查的目标；从受保护主干或团队约定基线创建。
- 使用清晰前缀：`feat/`、`fix/`、`refactor/`、`docs/`、`chore/`；分支名描述目标而非个人姓名。
- 不在未经确认的情况下覆盖、重置或删除他人已有改动。

## 提交

- 提交应小而完整，并保持构建和关键测试可用。
- 推荐 Conventional Commits：`feat:`、`fix:`、`refactor:`、`docs:`、`test:`、`chore:`。
- 提交信息说明“为何改变”，必要时在正文描述影响和迁移要求。

## 合并与评审

- 合并前检查差异范围、冲突处理、验证结果和敏感信息泄露。
- 不提交密钥、令牌、个人配置、构建产物或无关格式化改动。
