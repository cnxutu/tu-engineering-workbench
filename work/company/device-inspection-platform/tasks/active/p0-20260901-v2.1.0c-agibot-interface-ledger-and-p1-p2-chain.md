> 范围：仅覆盖“机器狗巡检监控（智元 D1 Max）”与“驾驶舱（智元 D1 Max）”原型，以及 P1 消费 P2 消息和 P1 下行控制链路。

## 1. 使用方式与口径

这不是字段设计稿，也不冻结 URL、identifier 或协议号。今天与产品、前端、适配器同事逐项确认时，只先确认每一项的结论：

| 标记 | 含义 |
|---|---|
| **已有可复用** | 当前分支已有同一业务语义的入口；机器狗只接入数据即可使用。 |
| **已有需改** | 当前分支有技术入口或相近页面接口，但现有 DTO、分类、状态或设备语义不覆盖机器狗。 |
| **全新** | 当前分支没有可承载该机器狗业务语义的 P1 接口/消息契约。 |
| **待确认** | 原型可见，但数据源、是否纳入本版本或复用边界尚未冻结；不能据此排入已承诺开发。 |

“已有”只表示代码中存在，不代表可直接交给前端，也不代表智元适配器已经支持。所有“已有需改/全新”都应由前端、P1 和适配器共同确认后，再进入字段级接口文档。

## 3. P1 消费 P2 上行消息：现状与机器狗兼容点

### 3.1 当前已验证链路

```text
机器人 / SDK
  → P3/适配器编码为 IotDeviceMessage
  → P2：设备上行处理、属性/运行态处理
  → P2 Data Rule：RocketMQ 投递完整 IotDeviceMessage
  → iot_business_event : DEFAULT_FLOW
  → P1 InspectionIotUpstreamConsumer
  → InspectionIotMessageConverter（可按 params 展开）
  → InspectionIotMessageRouter（按 identifier 唯一路由）
  → 对应业务 Handler → P1 缓存/业务数据/WebSocket/页面
```

已验证配置中，P1 上行默认订阅为 `iot_business_event:DEFAULT_FLOW`。P1 路由器遇到**未知 identifier 会记录错误后确认消费**，不会等待“后续版本自然兼容”。因此“适配器先上报、P1 Handler 后补”会导致消息被消费但机器狗页面没有业务效果。

### 3.2 上行兼容台账

| 项目 | 当前链路是否已有 | 机器狗要做的调整 | 主要负责人 |
|---|---|---|---|
| P2→P1 RocketMQ 通道 | **已有可复用** | 复用 `iot_business_event:DEFAULT_FLOW` 的前提是机器狗消息被正确的 Data Rule 命中；不能只导入物模型而不配规则。 | P2 + P1 联调 |
| P1 消费入口、消息转换、identifier 路由 | **已有可复用** | 不改入口；为每个最终 identifier 注册唯一 Handler，并准备完整/缺字段/重复/乱序样本。 | P1 |
| 机器狗运行状态（电池、模式、运动、速度、里程、避障、充电、急停、定位等） | **全新业务 Handler** | 不建议直接扩写 DJI 状态 DTO；确定统一“地面机器人状态”模型后新增 Handler、快照缓存和页面转换。 | P1 + 适配器 |
| 机器狗故障及恢复 | **全新业务 Handler** | 明确故障 identifier、等级、恢复事件、幂等键和合并规则；P1 再决定落库/告警查询/推送。 | P1 + P2 + 产品 |
| 在线/离线 | **已有需改** | P2 可维护通用设备运行态；P1 业务状态需定义“SDK 无状态 N 个周期”“RTSP 断流”“定位丢失”各自是否离线/异常。 | P1 + P2/P3 |
| 地图坐标/姿态 | **全新业务处理** | 先确认 PGM 本地坐标、项目中心点、标定矩阵、时间戳和定位失效策略；无此契约不得承诺地图定位。 | P1 + 产品 + 适配器 |
| P1 向前端实时推送 | **已有需改** | 复用 WebSocket 通道，新增机器狗快照/告警/控制权变更消息；首屏 REST 快照与 WS 增量的版本和兜底规则后定。 | P1 + 前端 |

### 3.3 上行联调必须先拿到的四类样本

1. 正常运行状态（一条完整、一条最小、双电池缺失一块的样本）。
2. 故障出现、同故障重复、故障升级、故障恢复各一条样本。
3. 在线、断线、重连及 PGM/定位丢失样本。
4. 当前任务开始、进行、暂停、失败、完成样本；若本版无机器狗任务，则明确标为不做。

## 4. P1 下行到 P2/设备：现状与机器狗兼容点

### 4.1 当前已验证链路

```text
前端 P1 Controller
  → P1 业务服务（权限、项目、控制权、审计、命令白名单）
  → InspectionIotCommandService / InspectionIotDeviceServiceImpl
  → P2 IoTDeviceApi.invokeDeviceService
  → P2 校验“目标设备产品下存在该服务 identifier”并路由到设备网关
  → P3 协议实例 / Codec / 适配器
  → 智元 SDK / 机器人
  → 服务回执、状态上报或失败事件回到上行链路
```

`InspectionIotDeviceServiceImpl` 已把命令 DTO 组装为 `IoTDeviceApi.invokeDeviceService` 请求；P2 下行会要求目标产品已发布、设备可解析网关归属，并根据该设备产品的真实 TSL 校验服务。故**P1 新接口完成不等于可下发**：没有 P2 产品、服务物模型、网关归属或适配器映射时，命令会在链路中失败。

### 4.2 下行兼容台账

| 项目 | 当前链路是否已有 | 机器狗要做的调整 | 主要负责人 |
|---|---|---|---|
| P1→P2 设备服务调用 | **已有可复用** | 复用 `IoTDeviceApi.invokeDeviceService` 和 P1 `InspectionIotCommandService` 的调用机制。 | P1 |
| P2 服务 TSL 校验与网关路由 | **已有可复用** | 为机器狗产品导入并发布最终服务 identifier；校验 `deviceId`、产品、网关归属一致。 | P2 |
| 机器狗低频命令（姿态/模式/速度/补光/自主充电） | **全新业务命令** | P1 新增机器狗命令 DTO、白名单、权限、审计、错误映射；P2/适配器定义对应服务和回执。 | P1 + 适配器 |
| 控制权 | **已有需改** | 可复用登录人、数据权限、日志基础能力；新增机器狗独占、抢占、外部占用、失联释放、会话超时规则。 | P1 + 产品 + 适配器 |
| 手动控制 | **全新** | 不复用无人机 DRC。先定“P1 发按键状态/目标向量”还是“P1 高频透传”；推荐由持有 SDK 连接的一侧维持 50Hz 与超时归零，P1 负责会话、鉴权、审计和状态变更。 | P1 + P3/适配器 |
| 急停/恢复 | **全新** | 单独服务、权限和审计；明确软/硬急停、恢复前置、设备 ACK 与状态确认，不走普通命令自动重试。 | P1 + P2 + 适配器 |
| 指令完成语义 | **已有需改** | P1 现有同步/异步调用能力可用；对每个机器狗命令明确“已发送 / 已受理 / 动作完成 / 失败 / 超时”。适配器底层发送成功不能直接写为动作完成。 | P1 + P2 + 适配器 |

## 5. 今日逐项对齐的最小清单

按以下顺序逐项填“复用/改造/新增/本期不做”和负责人，即可把本表继续沉淀为字段级接口定义：

1. M-01～M-04：先确认监控列表、点位、总览、业务状态是否必须本期交付。
2. M-05～M-08：确认详情、告警、任务、WebSocket 的数据来源与刷新频率。
3. C-01～C-02：确认驾驶舱首屏和双路 RTSP 是否纳入本期；视频仅展示还是由平台负责启停。
4. C-03～C-08：确认控制权、手动控制、急停、低频动作的权限和成功语义；这四项未经实机协议样本不得估为“直接复用”。
5. 固定每个上/下行 identifier 的 owner：适配器给出映射和样本，P2 配 TSL/Data Rule，P1 注册 Handler/命令门面，前端确认展示和错误态。

## 6. 当前结论与风险

- 当前 P1 分支 `develop/2.1.0` **具备可复用的 P2 消费链路、identifier 路由、IoT 服务调用和 WebSocket 基础设施**。
- 当前 P1 分支 **没有已完成的机器狗监控详情、驾驶舱、机器狗控制权、机器狗手动控制、机器狗急停或机器狗告警接口**。
- 现有无人机 DRC、机场控制权和直播接口不能以“接口已存在”为由直接计为机器狗完成量；它们最多减少基础设施工作，不减少机器狗业务契约、状态模型、适配器映射和实机联调工作。
- 最影响排期的前置是：最终物模型 identifier、P2 Data Rule、机器狗 50Hz 控制定责、控制/急停成功语义、地图坐标转换、RTSP 来源与鉴权。未冻结前，相关项应标记为阻塞而非进入开发完成率。
