## 缺陷记录

### FE-01：受理被显示为执行成功（模拟）

- 来源场景：P2 受理但设备状态未变化。
- 分类：实现缺陷，不是契约缺陷。
- 证据：接口契约 D-03 明确 `ACCEPTED` 只表示平台受理。
- 处理：前端提示改为“指令已发送，等待设备状态确认”；只有快照目标字段变化后才展示最终状态。
- 验收：模拟设备不回读时不会显示执行成功；稍后回读时状态正常更新。
- 状态：`verified`（演示）。

## 提测摘要（模拟）

- 提测范围：三灯状态首屏、三类开关动作、外部占用拦截、状态 WS 回显和重连 REST 回拉。
- 自动验证：示例假设 Controller、Service、权限、错误和 OpenAPI 检查均通过；真实任务必须记录实际命令和结果。
- 联调证据：示例假设前灯开关和外部占用已完成端到端验证。
- 未完成项：后灯、自动补光的真实设备闭环证据尚缺。
- 非目标：亮度、定时、批量、控制权获取/释放、执行超时状态机。
- 发布顺序：先确认 P2/适配器契约和能力，再部署 P1，最后开放前端入口。
- 回滚边界：前端关闭补光入口；P1 回滚新增 REST，不改变既有快照接口。

## G4 判断

`G4_test_ready=pending`。原因是后灯和自动补光的真实设备回读证据未齐；即使代码测试和前灯模拟链路通过，也不能把整个功能标记为设备闭环完成。
