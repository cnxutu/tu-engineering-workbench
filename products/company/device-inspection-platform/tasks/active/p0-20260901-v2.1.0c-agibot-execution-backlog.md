## 1. 任务边界与执行原则

本待办只覆盖巡检业务平台对机器狗的上行消费、状态/告警/控制权业务处理、前端 REST/WS 以及下行控制门面。物联网平台、网关、协议适配器、SDK 映射和设备连接由后端同事负责；P1 不替其实现协议编解码、SDK 连接或 50Hz 持续下发。

| 标记 | 含义 |
|---|---|
| 外部待对齐 | 需要你与后端同事/产品/前端共同冻结的契约或运行前置；我不能替代确认。 |
| P1 待实施 | 契约冻结后，可由我在 `c-drone-inspection` 实施的代码任务。 |
| 阻塞 | 缺少该项时，后续任务不能进入联调或不能声称功能完成。 |
| 可并行 | 前置条件满足后，可与同阶段其他任务同时开发。 |

**总门禁：** 所有样本均须脱敏；HTTP 成功、P2 服务已受理、适配器 ACK、设备状态已变化是四种不同语义，前端显示必须按冻结后的语义处理。

| A-08 | **手动遥控安全边界。** 50Hz 发送位置、P1 请求频率、控制量 TTL、浏览器断线/外部抢占/连接丢失后的归零策略。 | 后端同事主责；你确认产品体验 | B-08 | 明确由持有 SDK 连接的一侧 50Hz 持续下发；P1 不承担 HTTP 50Hz 循环；有自动归零证据。 |
| A-09 | **急停与控制权。** 软/硬急停状态、解除限制、权限矩阵、控制权抢占/释放/外部占用、审计要求。 | 你 + 产品 + 同事 | B-06、B-07、B-08 | 急停与恢复互斥规则、控制权状态机和前端可操作条件均书面冻结。 |

```text
  ↓

  ↓

  ↓

```

最小演示里程碑是 **B-03**：测试机器狗状态消息从 P2 进入 P1，路由到机器狗 Handler，完成设备分类校验并形成可查询状态快照。未达到该里程碑前，不开始承诺驾驶舱、控制或地图页面的交付时间。

## 5. 你与同事开会时可直接使用的收口问题

1. 这台测试机器狗的 `deviceId`、SN、`categoryCode`、项目/空间绑定分别是什么？请现场通过 P2 查询结果核验。
2. 状态上报 `params.identifier` 的最终值是什么？请给能直接进入 `thing.property.post` 的完整脱敏 MQ JSON。
3. 故障、控制权、命令回执是否采用独立 identifier？若复用现有名称，谁负责把 payload 适配成 DJI 结构？
4. Data Rule 具体投递哪些消息；哪些高频字段被明确过滤；P1 Consumer 的 Topic/Tag 是否无需调整？
5. `businessStatus` 的枚举、优先级、离线阈值是什么？急停和外部控制权是否覆盖“工作中/异常”状态？
6. 地图经纬度由谁给、什么坐标系、位置失效多久、离线显示最后位置还是隐藏？
7. 每一条下行命令的“已受理”“设备 ACK”“执行完成”“失败/超时”分别对应什么消息和字段？
8. 50Hz 遥控在谁那里定时发送，P1 应以什么频率发目标控制量，何时必须自动归零？
9. 急停/恢复、控制权抢占和外部占用如何互斥？哪些状态需要实时推送前端？
10. 前后 RTSP 如何拉取、鉴权、关闭和上报不可用？算法流启动是否复用现有入口？

## 6. 当前不能开始实施的事项

| 事项 | 原因 | 解除条件 |
|---|---|---|
| 机器狗状态 Handler 的最终 identifier 常量 | 当前 TSL 仅有名为 `identifier` 的属性，未定义它的实际取值。 | A-02 关闭。 |
| 告警/控制权/命令回执 Handler | 当前 TSL 的两个事件 identifier 与 DJI Handler 同名且 payload 不兼容，且无命令回执事件。 | A-03、A-04 关闭。 |
| 地图位置接口 | 当前 TSL 无经纬度，不能把本地 `motionPositionX/Y/Z` 当地理坐标。 | A-06 关闭。 |
| 遥控、急停与控制结果页面 | 下行服务是 async，且 50Hz、ACK、控制权、急停安全规则未冻结。 | A-07、A-08、A-09 关闭。 |
| 双路视频 | 当前机器狗 RTSP 与现有无人机直播链路的复用范围未确认。 | A-10 关闭。 |
